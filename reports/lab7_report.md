# Отчёт по лабораторной работе

**Тема:** Графический приёмник на Dear ImGui: просмотр сигнала во время приёма и настройка SDR на ходу

## Цель работы
Заменить статичные графики `read.py` интерактивным окном на Dear ImGui (ImPlot), в котором видны амплитуда сигнала, найденные пакеты, созвездие и показатели качества приёма. Добавить режим просмотра во время приёма: `./main rx` передаёт сэмплы по UDP, окно обрабатывает их в реальном времени. Сделать управление параметрами приёмника и передатчика из окна без перезапуска программ.

## Краткое содержание
Обработка сигнала осталась прежней (лабораторные работы №5–6): поиск пакетов, символьная синхронизация, снятие фазы по преамбуле, определение модуляции, декодирование, BER и EVM. Изменились способ показа результатов и источник данных:

| Режим | Источник сэмплов | Запуск |
|-------|------------------|--------|
| Файл | `rx_down.pcm` / `rx_up.pcm` или любой `.pcm` | `python3 read.py down` |
| Live | UDP от `./main rx` во время приёма | `python3 read.py live down` |

Окно построено на библиотеке `imgui-bundle` (Dear ImGui, ImPlot, hello_imgui). Кадр перерисовывается целиком на каждом шаге (immediate mode), поэтому изменение параметра сразу отражается на графиках.

### Интерфейс окна
Слева панель настроек шириной 340 пикселей, её можно растягивать. Панель состоит из сворачиваемых разделов, у параметров есть подсказки при наведении на значок «?».

| Раздел | Содержимое |
|--------|------------|
| Файл | кнопки «Канал down» / «Канал up», поле пути к `.pcm`, загрузка (только в режиме файла) |
| Приём (live) | состояние приёма, пауза, порт, принято секунд, датаграмм, скорость, потери, задержка графика |
| Приёмник SDR / Передатчик SDR | параметры `./main rx` и `./main tx`, меняются на ходу (только live) |
| Вид | длительность и амплитуда сигнала, ширина окна просмотра, «К максимуму», «Весь файл» / «Весь буфер», показ порога и начал пакетов |
| Поиск пакетов | SPS, окно сглаживания огибающей, запас вокруг фронта, кнопка «Найти пакеты» |
| Созвездие | модуляция (Авто / BPSK / QPSK), определённая модуляция с |E[s²]| и |E[s⁴]|, «Только видимые пакеты» |
| Результат | число пакетов, порог, EVM, BER, доля пакетов без ошибок, бит в пакете, переход к соседнему пакету |
| Управление | подсказка по мыши и клавишам |

EVM, BER и доля пакетов без ошибок подсвечиваются цветом: зелёный — хорошо, жёлтый — посредственно, красный — плохо (например, BER < 10⁻⁴ зелёный, < 10⁻² жёлтый).

Справа четыре графика:
1. **Амплитуда |I + jQ| во времени** с горизонтальной линией порога детектора и вертикальными метками начал найденных пакетов. Рисуется только видимая часть сигнала; если в ней больше 4000 точек, каждая группа отсчётов заменяется парой min/max, чтобы не терять пики.
2. **Созвездие** в равном масштабе по осям, с осями-границами решений и идеальными точками выбранной модуляции. По умолчанию показываются символы только тех пакетов, которые видны на графике амплитуды: так можно рассмотреть отдельный пакет. Рисуется не больше 50 000 символов.
3. **Гистограмма момента отсчёта в символе**: при хорошей синхронизации — один столбец.
4. **Ошибки в пакетах**: число битовых ошибок каждого пакета на той же оси времени, что амплитуда, с границами видимого окна.

Графики масштабируются колесом мыши, двигаются перетаскиванием, двойной клик вписывает всё. Стрелки ←/→ переходят к соседнему пакету, пробел ставит live на паузу.

### Передача сэмплов по UDP (`main.cpp`)
`./main rx` после записи каждого буфера в файл отправляет его копию на `127.0.0.1`: порт 5555 для канала `down`, 5556 для `up`.
- Буфер режется на датаграммы по 360 отсчётов. В начале каждой датаграммы — `uint64` с номером её первого отсчёта от начала приёма, дальше I/Q в формате int16 как в файле. Размер датаграммы 8 + 360 · 4 = 1448 байт, это меньше MTU, поэтому IP-фрагментации нет (фрагментированные датаграммы на loopback в WSL теряются).
- Отправка идёт с флагом `MSG_DONTWAIT`. Если окно не запущено или не успевает, датаграммы теряются, но приём и запись файла не тормозят.

### Приём в окне (режим live)
1. **Кольцевой буфер.** Отдельный поток принимает датаграммы и кладёт отсчёт с номером k в ячейку k mod 500 000 (500 мс сигнала). Приёмный буфер сокета увеличен до 4 МБ. По номеру отсчёта видны потерянные датаграммы: их место заполняется нулями, отсчёты считаются потерянными. Если номера начались заново, значит `./main rx` перезапущен, и буфер очищается.
2. **Поиск пакетов в фоне.** Второй поток раз в 50 мс ищет пакеты только в новых отсчётах, захватывая конец прошлого участка (пакет и запас вокруг него), чтобы найти целиком пакет, разрезанный границей. Новые пакеты добавляются к найденным раньше, повторы отбрасываются, пакеты, ушедшие из буфера, удаляются. При изменении параметров поиска или перезапуске `./main rx` поиск идёт заново по всему буферу.
3. **Плавная прокрутка.** Отсчёты приходят пачками, поэтому правый край графика не привязан прямо к последнему отсчёту. Он движется равномерно со скоростью 1 млн отсчётов/с и плавно подтягивается к положению «принято минус отставание». Отставание не меньше 100 мс и такое, чтобы на видимом участке поиск пакетов уже прошёл. Оно сразу растёт и медленно уменьшается. Ось амплитуды фиксирована по максимуму буфера, чтобы масштаб не прыгал. Время по оси отсчитывается от начала приёма.
4. **Пауза.** На паузе данные не обновляются, график можно двигать и масштабировать, приём при этом продолжается.

### Настройка SDR во время работы
`./main rx` и `./main tx` открывают управляющий UDP-порт на `127.0.0.1`: порт данных канала + 10 для rx (5565 / 5566) и + 20 для tx (5575 / 5576). Команда — текст `ключ=значение ...`. Процесс проверяет порт без ожидания между буферами, применяет команду через SoapySDR и отвечает текущими настройками в том же виде, вместе с допустимым диапазоном усиления. Пустая команда — только запрос настроек.

| Процесс | Ключ | Что задаёт |
|---------|------|------------|
| rx | `freq` | частота приёма, Гц |
| rx | `gain` | усиление приёмника, дБ |
| rx | `agc` | АРУ AD9361: 1 — включена, 0 — выключена |
| tx | `freq` | частота передачи, Гц |
| tx | `gain` | усиление передатчика, 0…89 дБ |
| tx | `amp` | амплитуда символа, 0…2047 (у QPSK по I и Q — amp/√2) |
| tx | `mod` | модуляция: `bpsk` или `qpsk` |

При смене `amp` или `mod` передатчик заново собирает буфер с пакетом, следующие пакеты уходят уже с новыми параметрами.

В окне разделы «Приёмник SDR» и «Передатчик SDR» показывают эти настройки и меняют их:
- частота — поле ввода (Enter), кнопки +/− меняют на 100 Гц, с Ctrl — на 10 кГц;
- усиление — ползунок в диапазоне, который сообщил процесс; при включённой АРУ ползунок приёмника неактивен;
- амплитуда и модуляция передатчика — ползунок и выпадающий список.

Окно раз в 0,5 с запрашивает настройки. Изменения отправляются не чаще раза в 50 мс, поэтому при движении ползунка процесс не заваливается командами. Ещё 1 с после изменения виджет показывает своё значение, а не ответ процесса, чтобы ползунок не дёргался назад. Если ответа нет дольше 1,5 с, раздел показывает «Нет связи». Подстройкой частоты приёмника можно вручную убрать сдвиг частоты между SDR, из-за которого созвездие вращается.

Без окна управлять можно любой UDP-утилитой:
```bash
echo -n "gain=40" | nc -u -w1 127.0.0.1 5565
```

### Ключевые параметры
| Параметр | Значение |
|----------|----------|
| GUI | Dear ImGui + ImPlot (`imgui-bundle`) |
| UDP-порты данных | 5555 (`down`), 5556 (`up`) |
| Управляющие порты | 5565 / 5566 (rx), 5575 / 5576 (tx) |
| Отсчётов в датаграмме | 360 (1448 байт) |
| Кольцевой буфер live | 500 000 отсчётов (500 мс) |
| Период поиска пакетов | 50 мс |
| Наименьшее отставание графика | 100 мс |
| Точек на графике амплитуды | до 4000 (прореживание min/max) |
| Символов на созвездии | до 50 000 |
| Запрос настроек / отправка изменений | 0,5 с / не чаще 50 мс |

### Запуск
```bash
pip install numpy imgui-bundle

# просмотр записанного файла
python3 read.py down              # или up, или путь к .pcm
python3 read.py down qpsk         # модуляция вручную

# просмотр во время приёма: каждая команда в своей консоли
./main tx usb:1.3.5 down
./main rx usb:1.5.5 down
python3 read.py live down         # можно добавить bpsk или qpsk
```

## Вывод
Приёмник получил интерактивный интерфейс: сигнал, найденные пакеты, созвездие, момент отсчёта и ошибки видны в одном окне, а параметры поиска и модуляцию можно менять с мгновенным пересчётом. Режим live показывает сигнал во время приёма с задержкой около 100 мс и не мешает записи файла. Управляющий UDP-канал позволяет менять частоту, усиление, амплитуду и модуляцию работающих `./main rx` и `./main tx` и сразу видеть результат на созвездии и в BER.
