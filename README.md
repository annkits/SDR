# SDR — Производственная практика по программно-определяемому радио

Репозиторий содержит материалы производственной практики по работе с **Software-Defined Radio (SDR)** на базе **Adalm-Pluto**.

Основные направления:
- Работа с **GNU Radio Companion**
- Приём и анализ реальных радиосигналов (FM, Wi-Fi)
- Прямая работа с устройством через **SoapySDR** + поддержка **timestamp**
- Сборка и использование необходимых библиотек (libiio, libad9361, SoapySDR, SoapyPlutoSDR)

### Lab 4 — Две SDR: прямой и обратный каналы
Используются две SDR: одна передаёт, другая принимает, отправка TX-буферов планируется по временным меткам FPGA. Есть два канала:

| Канал | Частота | Направление |
|-------|---------|-------------|
| `down` (downlink, прямой) | 433 МГц | SDR №1 → SDR №2 |
| `up` (uplink, обратный) | 434 МГц | SDR №2 → SDR №1 |

Передатчик отправляет буферы по 1920 отсчётов, чередуя сигнал и тишину, поэтому на приёме амплитуда имеет вид прямоугольных импульсов (1920 отсчётов «вкл», 1920 «выкл», период 3.84 мс при 1 МГц). Каждый буфер планируется на 4 мс вперёд относительно timestamp текущего RX-буфера.

**Сборка:**
```bash
cd dev
mkdir -p build && cd build
cmake .. && make
```

**Запуск** (каждая команда в своей консоли, URI устройств — из `SoapySDRUtil --find`):
```bash
# downlink: SDR №1 передаёт, SDR №2 принимает на 433 МГц
./main tx usb:1.3.5 down
./main rx usb:1.5.5 down

# uplink: SDR №2 передаёт, SDR №1 принимает на 434 МГц
./main tx usb:1.5.5 up
./main rx usb:1.3.5 up
```
Формат: `./main <rx|tx> <uri> <down|up> [bpsk|qpsk]`. Сначала запускается TX, затем RX; остановка — Ctrl+C.  
Приёмник пишет I/Q-сэмплы (int16, little-endian) в `rx_down.pcm` или `rx_up.pcm` в текущей папке.

В `dev/rx_down.pcm` лежат тестовые данные, принятые SDR по каналу downlink (RX Gain = 20).

→ [Отчёт](reports/lab4_report.md) (описывает код из коммита `e4d4a79`)  
→ Код: [`dev/main.cpp`](dev/main.cpp), [`dev/read.py`](dev/read.py)  
→ Черновые отдельные программы приёма и передачи (CMake их не собирает): [`dev/rx_only.cpp`](dev/rx_only.cpp), [`dev/tx_only.cpp`](dev/tx_only.cpp)

### Lab 5 — BPSK и символьная синхронизация
Передатчик в чётных буферах шлёт пакет BPSK: преамбула Баркер-13 и данные PRBS-9, 10 отсчётов на символ, прямоугольный формирующий фильтр. Приёмник (`read.py`) находит пакеты по энергии и корреляции с преамбулой, пропускает сигнал через согласованный фильтр и выбирает момент отсчёта внутри символа.

→ [Отчёт](reports/lab5_report.md) (описывает код из коммита `b92a9d6`)

### Lab 6 — QPSK и декодирование
Данные пакета модулируются BPSK (179 бит на пакет) или QPSK (358 бит: первый бит пары задаёт знак I, второй — знак Q, амплитуда AMP/√2 по каждой оси); преамбула всегда BPSK. Приёмник снимает фазу несущей по преамбуле, сам определяет модуляцию, декодирует биты и сравнивает их с эталонной PRBS-9 (BER), считает EVM. Компенсации сдвига частоты между SDR нет. Сборка и запуск такие же, как в Lab 4; модуляция передатчика задаётся пятым аргументом:
```bash
./main tx usb:1.3.5 down qpsk   # bpsk по умолчанию
```
Символы поворачиваются на фазу преамбулы и нормируются к единичной мощности. Модуляция по умолчанию определяется автоматически по степеням символов: у BPSK |E[s²]| ≈ 1, у QPSK |E[s²]| ≈ 0 и |E[s⁴]| ≈ 1. Её можно задать вручную вторым аргументом `read.py` или в окне просмотра (Lab 7).

→ [Отчёт](reports/lab6_report.md)

### Lab 7 — Графический приёмник на ImGui, просмотр во время приёма, настройка SDR на ходу
`read.py` показывает результаты обработки из Lab 5–6 в интерактивном окне, умеет обрабатывать сигнал во время приёма и менять параметры работающих `./main rx` и `./main tx`.

**Визуализация:**
```bash
pip install numpy imgui-bundle
python3 dev/read.py down        # или up, или путь к .pcm файлу
python3 dev/read.py down qpsk   # модуляция вручную: bpsk или qpsk
```
Скрипт открывает окно на Dear ImGui (ImPlot). Слева панель из сворачиваемых разделов: выбор файла, вид, параметры поиска пакетов, модуляция и результат (число пакетов, EVM, BER и доля пакетов без ошибок с цветовой оценкой); у параметров есть подсказки при наведении. Справа графики: амплитуда |I + jQ| во времени (с порогом детектора и началами найденных пакетов), созвездие символов данных из пакетов, видимых на графике амплитуды, гистограмма момента отсчёта в символе и число ошибок в каждом пакете. Графики масштабируются колесом мыши и перетаскиваются, длинные участки рисуются с прореживанием min/max. Стрелки ←/→ переходят к соседнему пакету, пробел ставит live на паузу.

**Просмотр во время приёма:** `./main rx` кроме записи в файл отправляет каждый буфер по UDP на `127.0.0.1` (порт 5555 для `down`, 5556 для `up`, датаграммы по 360 отсчётов, в начале каждой — номер её первого отсчёта). Режим `live` принимает их в отдельном потоке в кольцевой буфер на 500 мс (по номеру отсчёта, потерянные датаграммы заменяются нулями и считаются), пакеты ищутся в фоновом потоке раз в 50 мс только в новых отсчётах и добавляются к найденным раньше, а график амплитуды плавно прокручивается за приёмом с отставанием не меньше 100 мс — так, чтобы на видимом участке поиск уже прошёл. На паузе график можно двигать и масштабировать:
```bash
./main rx usb:1.5.5 down              # в одной консоли
python3 dev/read.py live down         # в другой; можно добавить bpsk или qpsk
```
Приём от GUI не зависит: если окно не запущено или не успевает, датаграммы просто теряются, а файл пишется полностью.

**Настройка SDR во время работы:** `./main rx` и `./main tx` слушают управляющий UDP-порт на `127.0.0.1` — порт данных канала + 10 для rx (5565 / 5566) и + 20 для tx (5575 / 5576). Команда — текст `ключ=значение ...`, процесс применяет её между буферами и отвечает текущими настройками в том же виде (пустая команда — только запрос). В режиме `live` разделы «Приёмник SDR» и «Передатчик SDR» показывают эти настройки и меняют их сразу, без перезапуска:

| Процесс | Ключ | Что задаёт |
|---|---|---|
| rx | `freq` | частота приёма, Гц |
| rx | `gain` | усиление приёмника, дБ |
| rx | `agc` | АРУ: 1 — включена, 0 — выключена |
| tx | `freq` | частота передачи, Гц |
| tx | `gain` | усиление передатчика, 0…89 дБ |
| tx | `amp` | амплитуда символа, 0…2047 (у QPSK по I и Q — amp/√2) |
| tx | `mod` | модуляция: `bpsk` или `qpsk` |

Пример без GUI: `echo -n "gain=40" | nc -u -w1 127.0.0.1 5565`.

## Требования

- Adalm-Pluto SDR
- Ubuntu / Linux
- GNU Radio Companion
- CMake, g++, Python 3
- Библиотеки: SoapySDR, libiio v0.26, libad9361-iio, SoapyPlutoSDR (официальный, pothosware)

Лабораторные работы №3–4 делались на форке SoapyPlutoSDR с временными метками FPGA (TelecomDep, ветка `sdr_gadget_timestamping`) и libiio v0.24. С ними `main.cpp` перестал работать, поэтому субмодули переведены на официальный SoapyPlutoSDR и libiio v0.26. В официальном драйвере нет параметра `timestamp_every`, который передаёт `main.cpp`.

Инструкции по установке библиотек находятся в материалах лабораторных работ и в папках соответствующих субмодулей.
